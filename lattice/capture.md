# إعدادات وأوضاع الالتقاط

يتم التحكم في عملية الالتقاط في علامة التبويب «الكاميرات» من خلال زر أحمر واحد بعنوان **«التقاط الكل»**ولوحة**«إعدادات الالتقاط»** التي تحدد ما ينتج عن هذا الزر: أي الكاميرات تشارك في عملية الالتقاط، وأنواع التصدير التي تحفظها كل كاميرا، وما إذا كان الغالق يُطلق مرة واحدة أم بشكل مستمر أم على فترات زمنية محددة. توثق هذه الصفحة سير العملية بالكامل — التكوين، وعملية الالتقاط نفسها، ومكان حفظ الملفات على القرص، وكيفية إعادة معالجتها لاحقًا لتحويلها إلى منتجات معايرة. توجد عناصر التحكم الخاصة بالكاميرا والمصفوفة في [إعدادات الكاميرا](camera-settings.md).

{% hint style="info" %}
**تتطلب عمليات الالتقاط وجود مشروع مفتوح.** يتم تعطيل خيار «التصوير الكامل» (Capture All) ورمز الترس الخاص بـ «إعدادات التصوير» (Capture Settings) حتى يتم فتح مشروع («إنشاء مشروع أو فتحه لحفظ عمليات التصوير»). يتم حفظ كل عملية تصوير ضمن مجلد المشروع في `captures/`.
{% endhint %}

## جزء «إعدادات الالتقاط»

افتحه باستخدام **رمز الترس بجوار «التقاط الكل»**في قائمة الكاميرات بالشريط الجانبي، أو باستخدام زر**«فتح إعدادات الالتقاط...»** الموجود أسفل أي جزء من إعدادات الكاميرا. يظهر العنوان «إعدادات الالتقاط» مع زر الرجوع ←.

يتم حفظ اختياراتك هنا — الكاميرات المضمنة، وخانات الاختيار الخاصة بكل نوع، ووضع الالتقاط — **لكل مشروع** ويتم استعادتها عند إعادة فتحه.

### أوضاع الالتقاط

ثلاثة أزرار للأوضاع في الجزء العلوي من اللوحة:

| الوضع | وظيفته | الإعدادات الفرعية (الافتراضية) |
| --- | --- | --- |
| **مفرد** *(افتراضي)* | التقاط واحد عبر كل كاميرا محددة. | — |
| **مستمر**| عمليات التقاط متتالية حتى حدوث شرط إيقاف. | التوقف عند**عدد اللقطات** (الافتراضي 1) *أو* **مدة الالتقاط** (الافتراضي 10 ثوانٍ؛ الوحدات: ثوانٍ / دقائق / ساعات / أيام). |
| **الفاصل الزمني**(التصوير بفاصل زمني) | سلسلة من اللقطات وفقًا لمؤقت. |**عدد اللقطات / الفاصل الزمني**(الافتراضي 1) ·**كل**N وحدات (الافتراضي 5 ثوانٍ) ·**لمدة** N وحدات (الافتراضي 1 دقيقة). |

في الوضع المستمر أو وضع الفاصل الزمني، يتحول زر «التقاط الكل» إلى زر **إيقاف (N)** أثناء التشغيل، مع حساب اللقطات فور ظهورها. يؤدي ملء محرك الأقراص إلى إيقاف التشغيل (انظر [تدفق &quot;التقاط الكل&quot;](#the-capture-all-flow)).**يتم تشغيل الوضع &quot;المستمر&quot; على المصفوفات داخل الخلفية (جديد في الإصدار 1.3.0).** عندما تنتمي كل كاميرا في القائمة إلى مصفوفة (الكاميرات المستقلة مخفية أو مستبعدة)، لا يرسل الوضع «المستمر» طلبًا واحدًا لكل عملية التقاط: حيث تقوم الخلفية الخاصة بـ Chloros

بتشغيل حلقة التقاط نفسها، وتكتب مجموعة متزامنة واحدة بينما تختار المجموعة التالية، ويقوم الزر باستقصاء عددها. مع وجود كاميرات مستقلة في القائمة، يقوم Chloros

بالتقاط كل تمريرة على حدة كما كان الحال من قبل.

{% hint style="warning" %}
**التصوير السريع على نظام Windows

: احرص على استبعاد الخلفية (Chloros

) من Microsoft Defender.** يكلف الفحص في الوقت الفعلي لكل ملف تكتبه عملية التصوير عالية السرعة حوالي 30% من معدل التصوير في اختبارات MAPIR

(مئات الملفات في الثانية عند منطقة اهتمام صغيرة). يوفر مُثبِّت Windows

خيار **&quot;استبعاد الخلفية (Chloros

) من فحص Microsoft Defender (التقاط أسرع بكثير بالكاميرا؛ موصى به)&quot;**، وهو محدد افتراضيًا، ويزيل هذا الاستبعاد عند إلغاء التثبيت. إذا قمت بإلغاء تحديدها، فقم بإعادة تشغيل برنامج التثبيت مع تحديدها، أو أضف استثناءً لعملية Defender لـ `chloros-backend.exe` (في المجلد `backend` ضمن مجلد تثبيت Chloros

). عندما يستخدم Defender نواة معالج واحدة أو أكثر أثناء الالتقاط المستمر لمصفوفة ما، تسجل الخلفية الخاصة بـ Chloros

ذلك مرة واحدة في سجلها، مع تقديم هذين الحلين نفسهما.
{% endhint %}

### اختيار الكاميرات وأنواع التصدير

يلخص نص المساعدة في الجزء هذا الأمر: اختر الكاميرات وأنواع التصدير التي ينتجها خيار «التقاط الكل» — كل الخيارات مفعّلة افتراضيًا، ويتم حفظ الاختيارات مع هذا المشروع.

* تعمل أزرار **&quot;تحديد الكل&quot; / &quot;عدم تحديد أي شيء&quot;** على تبديل حالة خانة الاختيار الخاصة بكل كاميرا دفعة واحدة.
* **مفاتيح التبديل الجماعية لأنواع التصدير**(صفان من الأزرار):**كل ملفات Raw / كل ملفات Debayered / كل ملفات Preview / كل ملفات Radiance / كل ملفات Reflectance / كل ملفات Index**. كل خيار له ثلاث حالات ملونة: الأخضر ✓ = قيد التشغيل لكل كاميرا تدعمه، الكهرماني – = قيد التشغيل لبعض الكاميرات، الرمادي = لا شيء. يتم تعطيل زر التبديل عندما لا تدعم أي كاميرا متصلة هذا النوع. تتحول جميعها إلى اللون الرمادي أثناء تشغيل «التصوير الأسرع».
* **الصفوف الخاصة بكل كاميرا**: مربع اختيار للتضمين، بالإضافة إلى قائمة قابلة للتوسيع (▸/▾) لأنواع التصدير القابلة للتطبيق لتلك الكاميرا مع مربعات اختيار فردية. يعرض الصف عدد العناصر النشطة مثل &quot;4/6&quot;.

### أنواع التصدير والكاميرات التي تدعمها

توجد ستة أنواع للتصدير: **Raw، Debayered، Radiance، Reflectance، Preview، Index**. تظهر فقط الأنواع القابلة للتطبيق في صف كل كاميرا:

| نوع التصدير | المحتوى | RGB

(FRGB) | باير متعدد الأطياف (FRGN/FOCN/FNGB) | أحادي (M3M) |
| --- | --- | --- | --- | --- |
| **Raw** | فسيفساء باير (أحادي: النطاق الفردي) مباشرةً من المستشعر | ✓ | ✓ | ✓ |
| **مُزيل الفسيفساء** | إزالة الفسيفساء الخطية: إزالة الإزاحة المظلمة (DSNU) الخاصة بحزمة المعايرة من الملف الخام، ثم إزالة الفسيفساء مع مراعاة الحواف — بدون تصحيح الخطية أو تسوية المجال أو فصل الألوان. يتم الحفظ كملف RGB

TIFF

ذي 3 قنوات (أحادي: تدرج رمادي ذو قناة واحدة) | ✓ | ✓ | ✓ |
| **المعاينة** | سلسلة العرض الكاملة (توازن اللون الأبيض + جاما وفقًا لملف تعريف الكاميرا، بالإضافة إلى إعداد «الضوء الساطع» (RGB

) للكاميرا؛ متعدد الأطياف: تمدد الألوان الزائفة) | ✓ | ✓ | ✓ |
| **الإشعاع** | float32 واط/م²/سترلين/نانومتر عبر سلسلة القياس الإشعاعي الكاملة | — (غير متوفر) | ✓ | ✓ |
| **الانعكاس** | uint16 ρ (32768 = 1.0) | — (غير متوفر) | ✓ — يُعرض فقط عندما تحتوي الكاميرا على مستشعر ضوء DAQ (خاص بها أو موروث من المصفوفة) | مثل الطيف المتعدد |
| **المؤشر** | عرض مؤشر الغطاء النباتي (LUT) | — | ✓ — يتطلب تعبير مؤشر مُفعَّل وغير فارغ على الكاميرا، ولا يتوفر لأعضاء المصفوفة المدمجة (تمتلك المصفوفة مؤشرًا مشتركًا واحدًا) | — (يحتاج المؤشر إلى نطاقين أو أكثر؛ انظر [الكاميرات أحادية اللون ومؤشرات الغطاء النباتي](mono-indices.md)) |

لا تتوفر الإشعاع والانعكاس أبدًا لكاميرات RGB

— فالإشعاع لكل باير ليس ذا معنى بالنسبة لمستشعر ضوئي عريض النطاق.

### أسرع التقاط

مفتاح التبديل **⚡ أسرع التقاط — صيغة RAW فقط**(يظهر باللون البرتقالي عند التشغيل) يتجاوز جميع اختيارات التصدير ليجعلها**صيغة RAW فقط** — بالإضافة إلى تركيبة مجانية ذات مؤشر مدمج للمصفوفات — بحيث يتم حفظ الإطار بأسرع ما يمكن: يتم تخطي العمليات الحسابية الخاصة بالإشعاع/الانعكاس/العرض بالكامل في وقت الالتقاط.

{% hint style="info" %}
**يتم حفظ ملف `.daq` أيضًا.** عند تعيين مستشعر ضوء، لا يزال «التصوير الأسرع» يسجل قراءة DAQ المتجهة لأسفل (في مجلد `daq/` الخاص باللقطات) — بحيث يمكن إنشاء منتجات الإشعاع والانعكاس والمؤشر لاحقًا عن طريق إعادة المعالجة (انظر [إعادة معالجة عمليات التقاط البيانات](#re-processing-captures-into-calibrated-products)). كما أن Fastest Capture لا يؤثر سلبًا على اختياراتك في خانات الاختيار: فقم بإيقاف تشغيله وستعود هذه الاختيارات كما كانت.
{% endhint %}

### عناصر التحكم لكل مصفوفة

تحصل كل مصفوفة متصلة على بطاقة مجموعة خاصة بها في اللوحة:

* **مربع الاختيار «تضمين»** (ثلاث حالات عبر العناصر) واسم المصفوفة مع وضع العرض الخاص بها: «(مجمعة | منفصلة)».
* **مربع الاختيار**محاذاة**(**مفعّل**افتراضيًا): يقوم بتحويل ملفات العناصر المصدر وفقًا لملف تعريف محاذاة المصفوفة بحيث يتم تسجيل الصدور بالبكسل عبر الكاميرات. تظل الملفات الخام غير مُعدلة لكنها تحمل التحويل في بياناتها الوصفية. (يتم حساب ملف التعريف نفسه في [لوحة إعدادات المصفوفة](camera-settings.md#alignment-co-registration).) يتم حفظ ملفات أعضاء المصفوفة بالاتجاه الأصلي لكل كاميرا، مع تسجيل أي إعدادات**انعكاس**أو**دوران** في الملف بدلاً من تطبيقها.
* صفوف الكاميرات الأعضاء متداخلة داخل البطاقة.

تستضيف بطاقة المصفوفة أيضًا مسجلين. اعتبرهما **مراقبة مقابل تحليل**:

| المسجل | الدرجة | ما يسجله |
| --- | --- | --- |
| **● تسجيل فيديو الفهرس / ■ إيقاف التسجيل** *(المصفوفات المدمجة فقط)* | **المراقبة** | الفيديو المركب المباشر للفهرس المدمج بمعدل 10 إطارات في الثانية — 8 بت، دقة المعاينة، مع تضمين LUT. يتطلب مشروعًا مفتوحًا وعرضًا مباشرًا متدفقًا. يعرض الإطارات + الوقت المنقضي أثناء التسجيل. |
| **⦿ تسجيل سلسلة صور خام / ■ إيقاف التسلسل الخام** *(أي مصفوفة)* | **التحليل**| إطارات باير الخام بمعدل الالتقاط المباشر (بدون معالجة) بالإضافة إلى بيان لكل إطار وقراءات `.daq`، إلى `captures/bursts/`. بعد التسلسل، يظهر زر**إنشاء فيديو**: يعيد معالجة التسلسل دون اتصال بالإنترنت إلى فيديو معاير — مؤشر مدمج و/أو إشعاع / انعكاس / مؤشر لكل كاميرا — بالإضافة إلى ملفات TIFF اختيارية. يبدأ إنشاء المؤشر المدمج تلقائيًا عند إيقاف التسلسل. |

## مسار

<!-- SCREENSHOT-NEEDED: the sidebar during a capture — Capture All showing live "Capturing… 3/6" progress text, and (second capture) the result flash "Saved N files". -->

«التقاط الكل»

اضغط على **«التقاط الكل»** في قائمة الكاميرات بالشريط الجانبي:

1. تقوم كل كاميرا مضمنة ومرئية وغير متوقفة بالالتقاط باستخدام أنواع التصدير المحددة لها. **تعمل المصفوفات كمحفز واحد متزامن** (مجموعة واحدة متزامنة عبر جميع الأعضاء — انظر [مصفوفات الكاميرات المتعددة](arrays.md))؛ بينما تقوم الكاميرات المستقلة بالالتقاط بشكل فردي.
2. يتم تخطي الكاميرات المخفية (العين) أو الموقوفة مؤقتًا. لا يتم حظر المصفوفة بالكامل إلا عندما تكون *جميع* أعضائها مخفية أو موقوفة مؤقتًا.
3. كلما تم تعيين مستشعر ضوء، يتم حفظ قراءة DAQ المتجهة لأسفل المطابقة كملف `.daq` في مجلد `daq/` الخاص بالتسجيلات — حتى بالنسبة للتسجيلات الخام فقط — بحيث يمكن دائمًا اشتقاق المنتجات الإشعاعية لاحقًا.
4. يُظهر الزر التقدم المباشر — «جاري الالتقاط… تم/الإجمالي» — وفي الوضع المستمر/الفاصل الزمني يتحول إلى **إيقاف (N)**. لكل عنصر التقاط مهلة انتظار مدتها 300 ثانية.
5. عند انتهاء الدورة، تظهر نافذة نتائج سريعة تعلن **&quot;تم حفظ N ملفًا&quot;**أو**&quot;تم حفظ N، فشل F&quot;**، بالإضافة إلى &quot;(S مخفي/موقوف مؤقتًا/تم تخطيه)&quot; في حالة تخطي الكاميرات. إذا امتلأ محرك الأقراص، يتوقف التشغيل ويُبلغ**&quot;توقف: محرك الأقراص ممتلئ. تم حفظ N، فشل F&quot;** — يُحسب كل ملف لم يتم كتابته على أنه فاشل.

## مكان حفظ عمليات الالتقاط

يتم حفظ عمليات الالتقاط ضمن المشروع المفتوح في `<project>/captures/`. يتم حفظ كل نوع تصدير في **مجلد فرعي خاص به**، لذا لا يخلط الالتقاط متعدد المستويات بين الأنواع أبدًا:

```
<project>/captures/
├── raw/           capture_<ts>_SN<serial>_raw.tif
├── debayered/     capture_<ts>_SN<serial>_debayered.tif
├── radiance/      capture_<ts>_SN<serial>_radiance.tif
├── reflectance/   capture_<ts>_SN<serial>_reflectance.tif
├── preview/       capture_<ts>_SN<serial>_display.tif
├── index/         per-camera vegetation-index (LUT) render, when Index is selected
├── composite/     array foreground/background live-view composite, when produced
├── clamp_masks/   radiance/…_clampmask.tif, reflectance/…, index/… — unmix clamp masks,
│                  one subfolder per product folder, only when a band was clamped
├── bursts/        raw-burst recordings (frames + manifest + .daq per burst)
└── daq/           the downwelling reading(s) matched to each capture (.daq), each with a
                   .daq.cameras.json naming the cameras it describes
```

* `<ts>` هو الطابع الزمني لالتقاط الصورة و`<serial>` هو الرقم التسلسلي للكاميرا. تُسمى عمليات الالتقاط المستقلة `capture_<ts>_SN<serial>_<level>`؛ أما عمليات الالتقاط المصفوفة من مشغل واحد متزامن فتُسمى `sync_<ts>_SN<serial>_<level>` و**تشترك في طابع زمني واحد لجميع الكاميرات في المجموعة** (يتم حذف لاحقة المستوى عندما تحفظ الكاميرا مستوى واحدًا فقط).
* **هناك اختلاف واحد يجب معرفته:** يتم تخزين مستوى العرض في مجلد باسم `preview/` بينما تحتفظ الملفات بـ `_display` في الاسم — يختلف المجلد واللاحقة لهذا المستوى فقط.
* تُخزَّن المستويات غير المعروفة في مجلد يحمل اسمها؛ وإذا تعذر إنشاء مجلد فرعي، يُسجَّل الملف في جذر اللقطات بدلاً من ضياعه.
* تُضغط ملفات TIFF الخاصة باللقطات بدون فقدان البيانات (DEFLATE) بشكل افتراضي، وتحتوي على بيانات التعريف الكاملة الخاصة بالمعايرة والمعالجة **داخل ملف XMP الخاص بالملف** — اللقطات ذاتية الوصف، ولا تحتوي على ملفات مصاحبة بخلاف ملف القراءة `.daq` (وملفه `.daq.cameras.json`).
* **أقنعة التثبيت (ميزة جديدة في الإصدار 1.3.0).**عندما يضطر الفصل الطيفي 3×3 إلى تثبيت نطاق عند القيمة 0 على بكسل واحد على الأقل، تحصل منتجات الإشعاع والانعكاس والمؤشر على قناع لكل بكسل، `clamp_masks/<product folder>/<product name>_clampmask.tif` (البت 0 = النطاق في قناة R للمنتج، البت 1 = G، البت 2 = B)؛ وتشير علامة XMP الخاصة بالمنتج `Chloros:UnmixClampMask` إليها. توجد الأقنعة**بجانب** مجلدات المنتجات، ولا توجد أبدًا داخل أي منها، لذا يمكن تسليم مجلد منتج مثل `reflectance/` إلى برنامج التصوير المساحي كما هو. يتخطى برنامج الاستيراد الخاص بـ «Chloros

» هذه الأقنعة.
* **الاتجاه (1.3.0).** يتم تدوير منتجات «المعاينة» و«الإشعاع» و«الانعكاس» و«المؤشر» الخاصة بالكاميرا المستقلة وفقًا لإعداد «الانعكاس/الدوران» الخاص بها؛ بينما تظل ملفات «Raw» و«Debayered» كما قرأها المستشعر. تظل جميع ملفات المصفوفة في صيغتها الأصلية. يُسجل كل ملف الإعداد في ملف XMP الخاص به، لذا تُطبق إعادة المعالجة هذا الإعداد بنفس الطريقة.
* **الكاميرا التي ينتمي إليها ملف `.daq` (1.3.0).** يتم مطابقة `.daq` الخاص بالالتقاط، في وقت المعالجة، فقط مع الصور الواردة من الكاميرات التي يحددها `.daq.cameras.json`. وبالتالي، فإن الكاميرا المستقلة التي لا تحتوي على مستشعر ضوء خاص بها لم تعد تستعير قراءة كاميرا أخرى — قم بربط مستشعر بها، أو سجل واحدًا في علامة التبويب «مستشعرات الضوء». لا يزال تسجيل مستشعر الضوء (وأي `.daq` بدون هذا الملف، بما في ذلك اللقطات الأقدم) يخدم كل كاميرا.

هذا هو نفس التخطيط الذي يكتبه ملفا `chloros-cli lattice capture` / `array-capture` في دليل `-o` الخاص بهما — الموثق في [مرجع CLI

§ كيف يبدو مجلد اللقطات](../reference/cli-reference.md#what-a-captures-folder-looks-like).

## إعادة معالجة اللقطات لتحويلها إلى منتجات مُعايرة

الإطارات الأولية الملتقطة بالإضافة إلى ملف `.daq` المحفوظ هي كل ما تحتاجه سلسلة المعالجة — ولهذا السبب يُعد «التقاط أسرع» (Fastest Capture) آمنًا للاستخدام في العمل الفعلي.

* **واجهة المستخدم الرسومية (GUI)**: أضف مجلد اللقطات إلى مشروع ([إضافة ملفات إلى مشروع](../processing-images-gui/adding-files-to-a-project.md)) وقم بالمعالجة كالمعتاد.
* **واجهة سطر الأوامر (CLI

)**: وجه `process` إلى**جذر مجلد اللقطات**:

```bash
chloros-cli process "C:/ChlorosProjects/MyField/captures"
```

عادةً ما يستورد `process` المجلد الذي تحدده فقط، ولكن عندما لا يحتوي هذا المجلد على أي صور ويحتوي على مجلدات فرعية، فإنه يتنقل تلقائيًا إلى المجلدات الفرعية — وبالتالي يتم استيراد المجلدات الفرعية والمجلد `daq/` دفعة واحدة. يتم استيراد كل عملية التقاط كـ **صورة واحدة** مع إرفاق المستويات الأخرى كأوضاع عرض، وليس كصورة واحدة لكل مستوى.

كما أن تسمية مجلد فرعي لمستوى ما مباشرةً (مثل `…/captures/raw/`) تعمل أيضًا، لكنها تترك مجلد `daq/` خلفها — قم بنسخه جنبًا إلى جنب عند-تستمد منتجًا إشعاعيًا من `raw/`، وإلا فلن يكون هناك ما يمكن مطابقته مع الطابع الزمني.

{% hint style="warning" %}
**تبدأ المعالجة دائمًا من `raw`.** ضمن كل عملية التقاط، يُعد الإطار الخام مصدر مسار المعالجة؛ `debayered`، `radiance`، `reflectance`، و`preview` تظهر كأوضاع قابلة للعرض ولكنها لا تُعاد أبدًا عبر خط الإنتاج — إعادة معالجة منتج مشتق من شأنها إعادة تطبيق حسابات التظليل واللون والإشعاع المدمجة بالفعل في بكسلاته، لذا يرفض برنامج Chloros

ذلك بدلاً من إجراء معالجة مزدوجة. لا تتم معالجة عمليات العرض `index/` و `composite/` على الإطلاق (فهي مخرجات وليست لقطات). يتم حفظ مجلد «captures» **بدون** استيراد ملفات raw ويتم عرضه بشكل طبيعي، لكن `process` يتخطاه ويشير إلى ذلك؛ أما `--input-level {raw,debayered,processed}` فهو مخرج الطوارئ المتعمد الذي يفرض نقطة دخول. انظر [مرجع CLI

](../reference/cli-reference.md#what-a-captures-folder-looks-like) للاطلاع على رسائل التخطي الدقيقة.
{% endhint %}

هناك سلوكان آخران يستحقان المعرفة عند كتابة البرامج النصية لإعادة المعالجة:

* إن تشغيل `chloros-cli process` الذي طلب منتجات ولكنه **لم يكتب أي منتجات صور**يفشل بشكل واضح ويخرج بقيمة غير صفرية** — لن تحصل أبدًا على تشغيل فارغ صامت. تُبلغ عمليات التشغيل الناجحة عن عدد منتجاتها. (يُعتبر التشغيل المتعمد الذي يقتصر على البيانات الوصفية فقط نجاحًا أيضًا.)
* لا تشغل الصادرات المعالجة المعاد استيرادها أبدًا خانة البيانات الأولية للالتقاط — تظل البيانات الأولية الأصلية دائمًا مصدر مسار المعالجة.

## نظائر واجهة سطر الأوامر (CLI

)

يمكن تشغيل كل ما ورد في هذه الصفحة دون واجهة مستخدم. تتوافق أوضاع الالتقاط في واجهة المستخدم الرسومية (GUI) مباشرةً مع `chloros-cli lattice array-capture`:

| واجهة المستخدم الرسومية (GUI) | واجهة سطر الأوامر (CLI

) |
| --- | --- |
| فردي | `chloros-cli lattice array-capture` |
| مستمر | `array-capture --continuous [--count N] [--duration S]` |
| على فترات | `array-capture --interval S [--duration S]` |
| أسرع التقاط | `array-capture --fastest` |
| خانة الاختيار المُحاذاة | `--aligned / --no-aligned` |
| خانات اختيار نوع التصدير | `--processing LEVEL` أو `--levels L1,L2,…` (الافتراضي `all`) |
| تسجيل فيديو الفهرس | `chloros-cli lattice array-record` |
| تسجيل سلسلة لقطات خام / إنشاء فيديو | `chloros-cli lattice array-burst` / `array-build-video` |

توجد جداول العلامات الكاملة، وخيار الالتقاط المستقر بضبط التعريض التلقائي الذكي (`--smart`)، ونموذج المعدل المستمر في [مرجع CLI

، § أوضاع الالتقاط والمسجلات وإعادة المعالجة دون اتصال](../reference/cli-reference.md#capture-modes-recorders--offline-reprocess).
